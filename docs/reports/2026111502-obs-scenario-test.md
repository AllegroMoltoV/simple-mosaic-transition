# OBS Studio の実機でのシナリオテストの結果

## はじめに

2026-11-15 に、OBS Studio 33.0.1 のポータブル版で、[シナリオテスト](../scenario-test.md) の自動で判定するシナリオを実行しました。この文書は、その結果と、実行の中で見つかったテストの手順の誤りをまとめたものです。プラグインの不具合は見つかりませんでした。

## 検証環境

| 項目 | 値 |
| --- | --- |
| OS | Windows 11 Home 10.0.26300 |
| GPU | NVIDIA GeForce RTX 3060 Ti |
| OBS Studio | 33.0.1 のポータブル版。`OBS-Studio-33.0.1-Windows-x64.zip` の sha256 が公開値 `0d9436451c2d772b33428e3fdae9776f071895c335de17283176306fb72651d3` と一致することを確かめた |
| プラグイン | コミット 9a7414a のビルド (`RelWithDebInfo`) |
| キャンバス | 1920×1080、60 fps。S10 だけ 1280×720 |

## 検証結果

OBS Studio のログでは、プラグインが `plugin loaded successfully (version 1.0.0)` を出して読み込まれました。シーントランジションの一覧には、`GetSceneTransitionList` で `simple_mosaic_transition` の種類のトランジションが出ました。

前提の確認と、自動で判定する 9 シナリオとログの検査は、すべて合格しました。生の出力は `.logs/2026111546-scenario-run.log` と `.logs/2026111548-scenario-s8-verify.log` です。

| ID | 結果 | 記録した値 |
| --- | --- | --- |
| P1・P2 | 合格 | T バーを 0.45 で止めて 1 秒おきに撮った 2 枚が一致し、前のシーンのモザイクが写った |
| S1 | 合格 | 録画の最も暗いフレームの輝度の平均が 0.0002 |
| S2 | 合格 | 横に隣り合う画素が同じ値になる割合が、T バー 0.25 で 0.971、0.45 で 0.995、0.5 で 1.000、0.75 で 0.972 |
| S3 | 合格 | 暗転部分の長さ 0% で、0.49 が前のシーン、0.51 が次のシーンのモザイク |
| S4 | 合格 | 切り替えの途中で別のシーンへ切り替え、最後のプログラムが scene-c |
| S5 | 合格 | プロジェクター 3 枚を開いたまま、S2 と同じ画像 |
| S6 | 合格 | scene-b への切り替えの最も暗いフレームの輝度が 1.3、scene-a への切り替えが 103.1 |

| S10 | 合格 | 1280×720 で、0.45 が前のシーンのモザイク、0.5 がほぼ黒 |

全シナリオで、描画のスキップの増分は 0 でした。ただし、S5 でプロジェクターのウィンドウを 3 枚開いた間に、16 フレームのスキップがありました。この 16 フレームは、S5 の判定の前に、統計の基準を取り直して除いています。

## 実行の中で直したテストの手順の誤り

1 回目から 4 回目の実行は、テストの手順の誤りで止まりました。プラグインは直していません。

| 現象 | 原因 | 対策 |
| --- | --- | --- |
| `SetCurrentProfile` が 600 (ResourceNotFound) を返した | `CreateProfile` は作ったプロファイルへ切り替えるが、一覧への反映は UI のスレッドで後から行われる (obs-websocket の `RequestHandler_Config.cpp:279-295`) | 作成後は、現在のプロファイルとシーンコレクションが切り替わるまで待つ |
| T バーを 0.45 にしても、撮影した画像が前のシーンのままだった。ログに `User started manual transition` が出ていなかった | スタジオモードの中でプログラムを切り替えたトランジションの最中に、T バーを操作していた。OBS Studio は、トランジションの最中に新しいトランジションを始めない (`frontend/widgets/OBSBasic_Transitions.cpp:338-344`) | プログラムは通常のモードで切り替え、トランジションが終わってからスタジオモードに入る |
| 前のトランジションの終わりを待つ処理が、10 秒で時間切れになった | 手動のトランジションを取り消したあと、進み具合は 1 ではなく 0 を返す | OBS Studio と同じく、進み具合が 0 と 1 の間にあるときだけトランジションの最中とみなす |
| S5 が、描画のスキップ 13 フレームで不合格になった | プロジェクターのウィンドウを開く間のスキップを数えていた | プロジェクターを開いて落ち着かせてから、統計の基準を取る |

## 考察

S5 の 16 フレームのスキップは、トランジションを描いていない、プロジェクターを開く操作の間に起きました。そのため、プロジェクターのウィンドウを作る処理によるもので、このプラグインの描画の負荷によるものではないと考えています。トランジションの描画の GPU 時間は 1 フレームあたり 0.05 ms 程度 ([記録](../logs/2026-11-15-render-tests-and-gpu-time.md)) で、この推測と矛盾しません。

## 調べていない範囲

- 依頼者が普段使う OBS Studio と、`%PROGRAMDATA%` への導入では試していません。依頼者のユーザーテストで確かめます。
- S7 (ソースの非表示のトランジション) と音声は、依頼者のユーザーテストで確かめます。
- HDR の出力の設定では試していません。sRGB 以外の色空間は、描画の統合テストの `non-srgb` だけで確かめています。
